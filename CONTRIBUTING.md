# Contributing to ScopeBuddy

Thank you for helping improve ScopeBuddy. Bug reports and focused pull requests
are welcome. For larger changes, open an issue first so the intended behavior
and hardware impact can be discussed before implementation.

## Before submitting code or designs

1. Base the change on the current `main` branch and keep it focused.
2. Build the firmware with ESP-IDF 5.4.2.
3. Test behavior affected by the change. Clearly identify anything that could
   not be tested on the CrowPanel hardware.
4. Do not include build output, credentials, personal data, or unrelated files.
5. Identify every reused third-party file, snippet, asset, font, or design and
   its license in the pull-request description.
6. Do not copy additional Elecrow example code into ScopeBuddy unless Elecrow
   has published terms that clearly permit the intended use and distribution.

## Contributor License Agreement

Every contributor must read and accept the
[ScopeBuddy Contributor License Agreement 1.0](CLA.md). It lets you retain
copyright in your contribution while granting the project owner the rights
needed to:

- publish the contribution as part of the community edition;
- maintain and relicense the combined project; and
- offer separate commercial licenses without having to remove accepted
  contributions later.

Acceptance is recorded by checking the CLA confirmation in the pull-request
template. A pull request without that confirmation will not be merged. If you
contribute on behalf of an employer or another organization, confirm that you
are authorized to grant these rights.

The CLA does not allow contributors to relicense Elecrow code or any other
third-party material they do not own.

## Pull-request checklist

- Explain what changed and why.
- Describe firmware and hardware tests performed.
- Mention user-interface screenshots or oscilloscope measurements when they
  help verify the change.
- List third-party material and license implications, or explicitly state that
  none was added.
- Confirm the CLA statement in the pull-request template.

By participating, contributors should keep discussions technical, respectful,
and focused on improving ScopeBuddy.
